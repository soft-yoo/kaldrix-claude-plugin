## Startup and Discovery

1. Read the server instructions returned by MCP `initialize`.
2. Call `describe_kaldrix_mcp` when this guide has not already been loaded. Omit `resourceUri` for this overview; pass a URI from its input enum for one focused guide or catalogue. The tool returns the selected content directly; the client does not need `resources/read`. Examples of compact server contracts: `kaldrix://projects/installation-point-kinds` and `kaldrix://documents/agent-documentation-policy`. Prefer the installed BIM or service-estimation skill for a procedure; full project/estimation guide URIs remain fallback reads on demand.
3. For compact discovery, call `describe_kaldrix_mcp` with `resourceUri=kaldrix://mcp/tool-groups` and select the relevant domain. Read `kaldrix://mcp/service-catalog` when you need tool, scope and focused-resource details. Do not load every tool definition for a single task. Treat the runtime tool list as authoritative; never invent a tool name. Use exact input field names from its schemas, including nested parameters and array items; unknown fields are rejected instead of silently ignored.
4. Use the single complete `workspace` catalog on `/mcp` (also available at `/mcp/profiles/workspace`). All domains share this connection; no profile selection or switching is needed.
5. `tools/list` shows only tools this connection may use: the person's own permissions as approved on the consent screen (see "Permissions: you act as the person"), company modules that are on and the company type (wholesaler data tools only for SUPPLIER companies, invoices only for company workspaces). The global category tree `list_supplier_catalog_categories` is also available to other company types with `supplier.read`.
6. Inspect existing objects before a mutation and reuse identifiers returned by Kaldrix.
